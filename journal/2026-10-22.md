# 22.10.2026 — Sicherheitsupdate PHP (PHP2Shell)

## Plan

- [x] Prüfen, ob die Cloud von den neuen PHP-Sicherheitslücken betroffen ist.
- [x] PHP auf eine korrigierte Version aktualisieren.
- [x] Nextcloud nach dem Update kontrollieren.

## Durchgeführt

Am 21.10.2026 wurden zwei kritische Sicherheitslücken in PHP veröffentlicht
(CVE-2026-109618 und CVE-2026-109619, „PHP2Shell“). Sie erlauben das Ausführen
von Code über das Netz ohne Anmeldung. Betroffen sind alle PHP-Versionen bis
8.5.11, korrigiert ist die Version 8.5.12.

Im Container lief PHP 8.5.11, die Cloud war also betroffen.

    sudo docker compose pull --ignore-buildable
    sudo docker compose build --pull --no-cache app
    sudo docker compose up -d
    sudo docker exec nextcloud-app php -v

Ergebnis:

- PHP 8.5.11 → **8.5.12**
- Nextcloud 35.0.1 → 35.0.2 (automatisch beim Start des neuen Images)
- MariaDB, Redis und Caddy auf die neuesten Images aktualisiert

## Probleme

1. `docker compose pull` brach mit „pull access denied for nextcloud-ffmpeg“ ab.
2. Warnung: Die Variable `TRUSTED_DOMAINS` ist nicht gesetzt.
3. Nach dem Update meldete Nextcloud: „missing table 'oc_federated_invites'“.
   `occ upgrade` meldete „No upgrade required“.

## Lösungen

1. `nextcloud-ffmpeg` ist ein eigenes, lokal gebautes Image und existiert nicht
   auf Docker Hub. Es wird mit `build --pull` aktualisiert, `pull` braucht
   `--ignore-buildable`.
2. `TRUSTED_DOMAINS` in der `.env` ergänzen (offen).
3. Die Migration war in `oc_migrations` als ausgeführt eingetragen, die Tabelle
   fehlte trotzdem. Lösung: Debug-Modus kurz einschalten, die Migration der App
   `cloud_federation_api` erneut ausführen, Debug-Modus wieder ausschalten.

       occ config:system:set debug --value=true --type=boolean
       occ migrations:execute cloud_federation_api 1016Date202502262004
       occ config:system:set debug --value=false --type=boolean
       occ db:schema:check -v

   Ergebnis: „The live database schema matches the expected schema.“

## Gelernt

- PHP läuft nicht auf dem Ubuntu-Host, sondern im Nextcloud-Container. Ein
  `apt upgrade` auf dem Host hätte die Lücke nicht geschlossen. Das Update kommt
  über ein neues Image.
- Ein eigenes Image auf Basis eines fremden Images muss neu gebaut werden, damit
  es die Korrekturen des Basis-Images bekommt.
- Ein Eintrag „Migration ausgeführt“ in der Datenbank beweist nicht, dass die
  Änderung auch wirklich vorhanden ist. `db:schema:check` prüft den echten
  Zustand.
- Die Befehle `migrations:*` gibt es in `occ` nur im Debug-Modus.

## Notizen

    Verwaltung → Übersicht im Browser auf Warnungen prüfen.
